BadEgg v3.

A zero-dependency Python 3.10+ HTTP security gateway and reverse-proxy WAF designed to sit cleanly in front of self-hosted web services. BadEgg inspects inbound traffic, enforces token-bucket rate limits, redacts accidental secret leaks in responses, and maintains explainable, expiring exact-IP bans from a loopback-only operator console.

Inspection & modes

Monitor first, enforce with confidence.

Run in Monitor mode to score requests and record structured audit events without dropping legitimate traffic, then switch to Enforce with tunable risk profiles once thresholds match your upstream service.

Traffic control

Token-bucket rate limits & overload caps.

Per-IP token buckets throttle bursty scanners while global concurrency and payload caps protect small origin servers from slowloris-style exhaustion and oversized request bodies.

Outbound safety

Response secret-leak redaction.

Scans upstream responses before they leave the gateway to redact accidentally exposed API keys, bearer tokens, and private credentials before they reach the client.

Explainable bans

Expiring exact-IP decisions.

Automated and manual bans record the triggering rule, score, and expiry timestamp. The admin console binds strictly to loopback (127.0.0.1:8765) and writes privacy-preserving audit logs.

Architecture

Standard library only, auditable end to end.

No third-party runtime packages to pin or patch: BadEgg v3 runs on stock Python 3.10+ and evaluates cleanly against 10,020 SecLists attack payloads out of the box.

01

Reverse-proxy gate

Accepts HTTP traffic on 127.0.0.1:8080 (behind TLS termination or Cloudflare), normalizes paths, headers, and query parameters, and scores payloads before forwarding upstream.

02

Loopback operator UI

Exposes live metrics, rule hits, mode toggles, and ban management on 127.0.0.1:8765 so administration is never reachable from the public internet by default.

03

Connected to IDI’s edge

Complements the compiled hall-of-shame.v2.bin IPv4/IPv6 blocklist enforced at the Cloudflare Worker edge across this website and Noosphere Chat.

Operator surface

Every knob on this gateway is a setting the edge resolves per request.

Mode, risk profile, the token-bucket budget, ban lifetime, inspection switches and the allowlist are live configuration rather than a rebuild: settings that differ from the code defaults are written to KV, so a policy change lands on the next request instead of the next deploy. No KV? The same values export as BADEGG_* variables for wrangler.jsonc.

The gateway behind this page is where that resolution happens, and it is where the operator endpoints live - a session login, a config API, the list of addresses it is banning right now, and a call to lift one. The browser console that drives them ships with badegg-v3.
